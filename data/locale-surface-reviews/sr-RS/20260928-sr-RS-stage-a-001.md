### F02 — Course SEO defect — `basics/10`

Canonical English:
`Use short variable declarations with the colon-equals syntax inside functions, where implicit var declarations are permitted.`

Current localized description:
`Користите кратке декларације променљивих са синтаксом := унутар функција, где је дозвољена имплицитна декларација типа.`

Defect: `имплицитна декларација типа` turns the relation into an implicit type declaration. The page concerns short variable declarations replacing a `var` declaration whose type is inferred/implicit.

Revision acceptance:
- preserve `:=` short variable declaration;
- preserve function-only scope;
- preserve the relationship to a `var` variable declaration with implicit/inferred type;
- do not call this a type declaration;
- do not add teaching detail beyond canonical semantic scope.

### F03 — Course SEO defect — `methods/9`

Canonical English:
`Define interfaces as sets of method signatures and see how receiver choice determines whether a value or pointer implements one.`

Current localized description:
`Дефинишите интерфејсе као скупове потписа метода и сазнајте како избор примаоца одређује да ли интерфејс имплементира вредност или показивач.`

Defect: implementation direction is reversed; the interface is not the subject implementing a value/pointer.

Revision acceptance:
- receiver choice determines whether a value or pointer implements the interface;
- the interface remains the implemented contract;
- do not add method-set teaching beyond canonical scope.

### F04 — Course SEO defect / glossary consistency — `methods/11`

Canonical English:
`Model an interface value as an underlying concrete value and type, with method calls dispatched to that concrete type.`

Current localized description:
`Посматрајте вредност интерфејса као конкретну вредност и тип у основи, при чему се позив методе прослеђује одговарајућем конкретном типу.`

Defect: `тип у основи` blurs general Go **underlying type** with the interface's stored **underlying concrete type**. The reviewed glossary distinguishes:
- underlying type → `тип који је у основи`
- underlying concrete type → `конкретан тип који интерфејс садржи`
- concrete value inside the interface → `конкретна вредност у интерфејсу`
- underlying concrete value → `конкретна вредност сачувана у интерфејсу`

Revision acceptance:
- clearly express the interface value as containing a concrete value and concrete type;
- preserve dispatch of method calls to that concrete type;
- avoid wording that can be read as general Go underlying type;
- do not expand canonical semantic scope.
